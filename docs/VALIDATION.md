Чистая конфигурация и сборка завершились успешно. CTest: **40 из 40 записей прошли**, время итогового запуска — **3.65 секунды**. В состав входят 39 модульных тестов GoogleTest и один интеграционный набор `cli_integration`, содержащий 13 проверок консольного приложения. ## Воспроизведение

Ниже приведены команды без персональных путей окружения. Выполняйте их из настоящего корня проекта. `R:` должен быть свободен; путь `C:\Учебные проекты` замените родительской папкой, содержащей `search_engine`. Путь к Python замените путём своего установленного интерпретатора.

```powershell
subst R: "C:\Учебные проекты"
cmake -S R:/search_engine -B R:/search_engine/build-ascii -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release -DPython3_EXECUTABLE="C:/Python312/python.exe"
cmake --build R:/search_engine/build-ascii --parallel
ctest --test-dir R:/search_engine/build-ascii --output-on-failure
.\build-ascii\search_engine.exe
subst R: /D
```

Для проверки чистой сборки используйте ранее не существовавший каталог сборки либо другое имя вместо `build-ascii`. Не сопоставляйте сам проект с корнем виртуального диска: сопоставление должно указывать на его родительскую папку. При повторной работе с этим каталогом сборки восстановите то же сопоставление диска.

Python не требуется приложению или модульным тестам. Для повторения **полного** результата он нужен, поскольку без найденного Python 3 CMake не регистрирует `cli_integration`. Его наличие можно проверить отдельно:

```powershell
ctest --test-dir R:/search_engine/build-ascii -N -R cli_integration
```

Эта диагностическая команда выполняется, пока сопоставление `R:` активно.

## Что проверено

- Частоты слов, порядок идентификаторов, обработка пустых документов и полная замена индексной базы.
- Детерминированная индексация документов в рабочих потоках с ограничением их числа.
- Поиск по всем словам и отдельный режим частичных совпадений, устранение повторов слов запроса.
- Абсолютная и относительная релевантность, порядок равных результатов, лимиты выдачи и количество совпадений до ограничения.
- Чтение и запись JSON, стандартные и явно заданные пути, пути документов относительно конфигурации.
- Сохранение `docid` при отсутствующем документе и предусмотренные ТЗ сообщения об ошибках конфигурации.
- Unicode-пути, запрет перезаписи входных файлов через путь ответов, замена содержимого старого файла ответов.
- Справка CLI, некорректные параметры и повторная индексация документов и запросов в режиме `--watch`.

Опечатки `TestBasic2` и несовместимость исходного `TestTop5` с AND-поиском раскрыты в README. Успешные тесты не означают, что противоречивые исходные примеры прошли буквально без исправлений.
