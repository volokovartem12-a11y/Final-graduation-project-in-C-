# Публикация и сдача

Публикация ещё не выполнена: в текущем рабочем окружении не подтверждён доступ к GitHub. Эти команды предназначены для владельца GitHub-аккаунта. Они не отправляют проект куратору автоматически.

## Подготовка

1. Выполните команды сборки, тестов и запуска из README.
2. Проверьте результат в `answers.json` и отметьте фактически выполненные пункты `docs/CHECKLIST.md`.
3. Убедитесь, что `.gitignore` исключает каталоги сборки, временные файлы, IDE и сгенерированный `answers.json`. Локальные исходники зависимостей в `third_party` должны попасть в репозиторий.
4. Создайте в GitHub пустой публичный репозиторий `search_engine`. Не добавляйте на этом шаге автоматически README, лицензию или `.gitignore`: соответствующие файлы уже находятся в проекте.

## Загрузка в GitHub

Откройте терминал **в папке `search_engine`**, которая содержит `CMakeLists.txt`. Команды ниже создают отдельный репозиторий именно для финального проекта. Не выполняйте `git add .` из родительской папки с другими учебными работами.

`YOUR_GITHUB_LOGIN` в адресе — заменяемый пример, а не готовая ссылка. Подставьте свой логин. Для входа используйте штатную авторизацию GitHub; пароль или токен не следует записывать в файлы проекта.

```bash
git init -b main
git status --short
git add .
git diff --cached --stat
git commit -m "Implement local search engine"
git remote add origin https://github.com/YOUR_GITHUB_LOGIN/search_engine.git
git push -u origin main
```

Перед `git commit` проверьте список добавленных файлов: в нём должны быть исходники, тесты, ресурсы, CMake, документация и зависимости; не должно быть исполняемых файлов, каталогов сборки и личных данных. Если Git попросит имя и почту автора, задайте свои значения в настройках Git; не копируйте вымышленные данные.

Если в папке `search_engine` уже есть настроенный репозиторий, сначала проверьте `git status` и `git remote -v`; повторное создание `origin` не требуется.

## Проверка опубликованного проекта

Проверьте вкладку **Actions**: обе задачи сборки и тестов должны пройти. Откройте репозиторий без авторизации, чтобы убедиться в публичном доступе. Затем выполните сборку из свежего клона в отдельной папке:

```bash
git clone https://github.com/YOUR_GITHUB_LOGIN/search_engine.git search_engine-review
cd search_engine-review
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure
./build/search_engine
```

Для Windows используйте команды соответствующего генератора из README. После успешных проверок обновите чек-лист. Ссылка для сдачи имеет вид `https://github.com/YOUR_GITHUB_LOGIN/search_engine`; замените логин реальным.

## Текст для куратора

Отправляйте сообщение только после публикации и проверки ссылки. Шаблон следует заполнить фактическими результатами:

> Здравствуйте! Направляю финальную работу — локальный поисковый движок на C++17.
>
> Репозиторий: ВСТАВЬТЕ_РЕАЛЬНУЮ_ССЫЛКУ.
>
> Команды сборки и запуска, формат JSON и чек-лист находятся в README и папке docs. Локальные проверки: УКАЖИТЕ_КОМПИЛЯТОР_И_РЕЗУЛЬТАТ_CTEST. Статус GitHub Actions: УКАЖИТЕ_ФАКТИЧЕСКИЙ_РЕЗУЛЬТАТ.
>
> В README описаны противоречия исходного ТЗ: основной поиск выполняется по всем словам, а OR-режим отдельно воспроизводит пример TestTop5. Опечатки TestBasic2 исправлены в согласованных тестовых данных. Прошу проверить проект и сообщить замечания.

## Работа с обратной связью

Сохраните замечания куратора, внесите исправления, повторите сборку и тесты. Затем создайте коммит, выполните `git push` и сообщите куратору об обновлении через тот же канал. Получение обратной связи и её выполнение отмечаются в чек-листе только после фактического завершения.
